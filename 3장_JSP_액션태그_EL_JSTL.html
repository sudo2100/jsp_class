1 액션 태그란?

🎯 학습목표
  • 액션 태그의 역할과 XML 형식(<jsp:…/>)을 이해한다.
  • 대표적인 5가지 액션 태그의 용도를 구분할 수 있다.

📖 액션 태그(Action Tag)

JSP에서 객체 생성과 공유, 페이지 이동과 전달 등의 기능을 제공하는 태그입니다. <% … %> 같은 스크립트 태그 형식이 아니라 XML 형식 <jsp: … />를 사용합니다.

액션 태그형식설명
forward<jsp:forward … />다른 페이지로의 이동 등 페이지 흐름 제어
include<jsp:include … />외부 페이지의 내용을 포함하거나 페이지를 모듈화
useBean<jsp:useBean … />JSP 페이지에 자바빈즈를 설정
setProperty<jsp:setProperty … />자바빈즈의 프로퍼티 값을 설정
getProperty<jsp:getProperty … />자바빈즈의 프로퍼티 값을 얻어옴

2 자바빈즈(JavaBeans)와 useBean & 실습(Member)

🎯 학습목표
  • 자바빈즈의 개념과 로직 분리·재사용의 이점을 설명할 수 있다.
  • <jsp:useBean>으로 빈 객체를 검색/생성할 수 있다.
  • scope(생명주기 범위) 속성을 이해한다.

📖 자바빈즈(beans)란?

  • 자바 코드를 사용하여 자바 클래스로 로직을 작성하는 방법이다.
  • 자바 코드와 HTML을 함께 작성하면 기능 확장·재사용이 어렵다.
  • 화면 표현을 위한 계산식·자료 처리 자바 코드를 따로 분리하여 작성한다.
🔄 처리 흐름
① 웹 브라우저가 JSP에 요청 → ② JSP가 자바빈즈와 통신 → ③ 자바빈즈가 데이터베이스에 연결 → ④ JSP가 브라우저에 응답

🔧 useBean 액션 태그

자바빈즈를 사용하기 위해 실제 자바 클래스를 선언·초기화하는 태그입니다. 설정된 id, scope로 객체를 검색하고, 발견되지 않으면 빈 객체를 생성합니다.

<jsp:useBean id="식별 이름" class="자바빈즈 이름" scope="범위"/>
속성설명
id자바빈즈를 식별하기 위한 이름
class패키지 이름을 포함한 자바빈즈의 이름
scopepage(기본값), request, session, application 중 하나
💡 scope
생명주기 범위를 의미합니다. session으로 설정하면 세션 유효 범위 동안 해당 인스턴스의 상태가 유지됩니다.

📋 scope 4가지 정리 — 값이 어디서 공유되고 언제까지 유지되는지가 핵심입니다.

scope공유(생명) 범위내장 객체언제까지 유지?대표 사용 예
page (기본값)현재 JSP 페이지 안에서만pageContext그 페이지 실행이 끝나면 소멸한 페이지 내부의 임시 값
request하나의 요청~응답 (forward 포함)request응답이 완료되면 소멸forward로 넘기는 데이터
session브라우저(클라이언트)별session세션 종료(로그아웃·타임아웃)까지로그인 사용자, 장바구니
application웹 애플리케이션 전체 (모든 사용자 공유)application서버(웹앱)가 종료될 때까지방문자 수, 전역 설정

범위 크기: page < request < session < application (아래로 갈수록 더 넓게·오래 공유)

🧪 자바빈즈 실습 — Member

🎯 학습목표
  • 빈즈 클래스(Member)를 만들고 useBean으로 사용할 수 있다.
  • getProperty/setProperty로 값을 읽고 설정한다.
🧪 예제 ① 빈즈 클래스 — Member.java (package bean)
public class Member {

    private int id = 2025101;
    private String name = "우영우";

    public int getId() { return id; }
    public void setId(int id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}
🧪 예제 ② useBean + getProperty — member01.jsp
<!-- member는 Member 클래스의 인스턴스(객체) -->
<jsp:useBean id="member" class="bean.Member" scope="request" />

<p>아이디: <%= member.getId() %></p>
<p>이름: <%= member.getName() %></p>
🧪 예제 ③ setProperty로 값 설정 — member02.jsp
<jsp:useBean id="member" class="bean.Member" scope="request"/>
<jsp:setProperty property="id" name="member" value="2021102"/>
<jsp:setProperty property="name" name="member" value="안영이"/>

<p>아이디 : <jsp:getProperty property="id" name="member"/></p>
<p>이 름 : <jsp:getProperty property="name" name="member"/></p>
💡 name vs id
setProperty·getProperty의 name 속성은 useBean의 id(빈 식별 이름)를 가리킵니다.
🧪 예제 ④ import로 직접 객체 생성 — member03.jsp

액션 태그 대신 page import 후 스크립트릿에서 직접 new로 생성할 수도 있습니다.

<%
    // Member 클래스 - import
    Member member = new Member();
%>

<p>아이디: <%= member.getId() %></p>
<p>이름: <%= member.getName() %></p>

3 EL(표현 언어)이란? & 연산자와 표현식

🎯 학습목표
  • EL의 등장 배경과 ${...} 구문을 이해한다.
  • EL이 스크립트릿/표현식을 대체함을 안다.

📖 EL(Expression Language)

  • MVC 패턴에서 뷰(View) 역할의 JSP를 더 효과적으로 만들기 위해 개발되었다. (코드와 태그가 섞여 복잡해지는 문제 해결)
  • 자바 코드를 직접 쓰지 않고, 간단한 표현식으로 데이터(변수·객체·속성)에 접근하게 해준다.
  • JSP 2.0부터 도입, ${...} 구문 사용.
  • 내장 객체(request, session, application 등)에 담긴 속성 값을 쉽게 꺼낼 수 있다.

🔁 스크립트릿·표현식을 대체

<!-- 기존 방식 -->
<jsp:useBean id="test" class="TestBean" />
<%= test.getName() %>

<!-- EL 방식 -->
${test.name}
💡 EL 문법
$로 시작하고 {표현식}으로 표기합니다. 표현식은 변수 이름 또는 객체이름.멤버변수이름 구조이며, 기본 연산도 가능합니다.

🔢 EL 연산자와 표현식

🎯 학습목표
  • 산술·비교·논리·empty 연산자를 EL로 사용할 수 있다.

🔧 표현 언어 연산자

산술기능비교기능
+ - * /더하기·빼기·곱하기·몫== / eq, != / ne같다 / 같지 않다
%나머지< lt, > gt, <= le, >= ge대소 비교
논리 / 기타기능
&& / and, || / or, ! / notAND · OR · NOT
a ? x : y삼항 — a가 참이면 x, 거짓이면 y
empty <값>값이 null이거나 빈 문자열이면 true. 예: ${empty param.n}
🧪 예제 — el01.jsp (연산자 실습)
<h3>문자, 숫자 데이터 표현</h3>
${300}<br>
${"감사합니다."}<br>
${12 * 2}     <%-- 24 --%>
${12 / 2}     <%-- 6.0 --%>

<h3>비교, 논리 연산</h3>
${10 == 11}<br>   ${10 eq 11}<br>   ${10 != 11}<br>
${10 < 11}<br>    ${10 lt 11}<br>   ${10 > 11}<br>   ${10 gt 11}<br>

${(10 > 11) and (10 != 11)}<br>
${(10 > 11) or (10 != 11)}<br>

4 EL 내장 객체와 데이터 접근

🎯 학습목표
  • EL 내장 객체(request·session·application)를 안다.
  • 속성·배열·Map을 EL로 꺼낼 수 있다.

🗄️ EL 내장 객체(데이터 저장소)

내장 객체기능
requestrequest 영역 생명주기에서 사용되는 저장소
sessionsession 영역 생명주기에서 사용되는 저장소
applicationapplication 영역 생명주기에서 사용되는 저장소
🧪 예제 ① 객체·속성 접근 — el02.jsp
<!-- 현재 날짜 객체 생성1 (스크립트릿) -->
<% LocalDateTime datetime = LocalDateTime.now(); %>
<p>스크립트 출력 : <%= datetime %></p>

<!-- 현재 날짜 객체 생성2 (useBean + EL) -->
<jsp:useBean id="now" class="java.util.Date" />
<p>EL 출력 : ${now}</p><hr>

<!-- request에 데이터 저장 -->
<%
    request.setAttribute("name", "한강");
    request.setAttribute("age", 25);
%>
<p>이름: ${name}</p>   <%-- 한강 --%>
<p>나이: ${age}</p>    <%-- 25 --%>
🧪 예제 ② 배열·Map 접근 — el02.jsp
<!-- 배열, Map 접근 -->
<%
    String[] fruits = {"사과", "바나나", "포도"};
    request.setAttribute("fruits", fruits);
%>
<p>${fruits[0]}</p>   <%-- 사과 --%>
<p>${fruits[1]}</p>   <%-- 바나나 --%>

<%
    Map<String, String> map = new HashMap<>();
    map.put("k1", "korea");
    map.put("j1", "japan");
    request.setAttribute("map", map);
%>
<p>${map.k1}</p>      <%-- korea --%>
<p>${map["j1"]}</p>   <%-- japan --%>
💡 Map 접근
${map.k1}과 ${map["j1"]} 두 방식 모두 가능합니다. 배열은 ${arr[인덱스]}로 접근합니다.

5 JSTL 소개와 설치 & Core 태그

🎯 학습목표
  • JSTL의 개념과 5가지 라이브러리 구성을 안다.
  • Maven으로 JSTL 의존성을 추가하고 taglib로 선언할 수 있다.

📖 JSTL(JSP Standard Tag Library)

  • JSP에서 자바 코드 대신 사용할 수 있는 표준 태그 라이브러리이다.
  • 스크립트릿(<% %>)을 제거해 가독성을 높이고, 반복문·조건문·DB 연동 등을 태그로 간편하게 처리한다.
  • 핵심(Core)·XML·I18N(국제화)·데이터베이스(SQL)·함수(Function)로 구성되며, 보통 EL과 함께 사용한다.
라이브러리URI (Jakarta)prefix
Core(핵심)jakarta.tags.corec
I18N(포맷)jakarta.tags.fmtfmt
데이터베이스jakarta.tags.sqlsql
함수jakarta.tags.functionsfn

📦 Maven으로 JSTL 설치

Maven은 라이브러리의 버전·종속성 관리를 도와주는 빌드 도구입니다. 프로젝트를 우클릭 > Configure > Convert to Maven Project로 변환하면 pom.xml이 생성됩니다.

① pom.xml의 <dependencies>에 아래 2개 추가 → ② 프로젝트 우클릭 > Maven > Update Project

    <groupId>jakarta.servlet.jsp.jstl</groupId>
    <artifactId>jakarta.servlet.jsp.jstl-api</artifactId>
    <version>3.0.0</version>
</dependency>
<dependency>
    <groupId>org.glassfish.web</groupId>
    <artifactId>jakarta.servlet.jsp.jstl</artifactId>
    <version>3.0.1</version>
</dependency>

🏷️ JSTL Core 태그

🎯 학습목표
  • Core 태그(set·out·if·choose·forEach)의 형식과 용도를 안다.
  • 조건·반복 로직을 스크립트릿 없이 태그로 작성한다.

🔧 Core 태그의 종류

태그설명
<c:set>사용할 변수를 설정
<c:out>출력에 사용
<c:if>조건문 처리
<c:forEach>반복문 처리
<c:choose> / <c:when> / <c:otherwise>다중 조건문 처리
🧪 예제 ① set · out · if
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
...
<h3>set, out</h3>
<c:set var="product1" value="삼성 갤럭시"></c:set>
<c:set var="product2" value="애플 아이폰"></c:set>

<p>product1: <c:out value="${product1}"></c:out></p>
<p>product2: ${product2}</p>

<h3>if</h3>
<c:set var="checkout" value="true" />
<c:if test="${checkout}">
    <p>주문 제품: ${product2}
</c:if>

<c:if test="${!checkout}"> <!-- false이면 실행 -->
    <p>주문 제품이 아님
</c:if>

<c:if test="${not empty product1}"> <!-- empty이면 출력안됨 -->
    <p>${product1} 이미 추가됨
</c:if>
🧪 예제 ② forEach (배열 반복)
<h3>forEach</h3>
<!-- value="${[10, 20, 30, 40]}"도 가능 -->
<c:set var="intArray" value="${{10, 20, 30, 40}}" />
<ul>
    <c:forEach var="num" items="${intArray}">
        <li>${num}</li>
    </c:forEach>
</ul>
🧪 예제 ③ 짝수/홀수 판정 (c:if)

...

<c:if test="${num % 2 == 1}">

</c:if>

6 MVC 패턴과 실습

🎯 학습목표
  • MVC(Model·View·Controller)의 역할 분담을 설명할 수 있다.
  • 서블릿(컨트롤러)→JSP(뷰) 구조로 데이터를 전달·출력한다.

📖 MVC란?

웹 애플리케이션을 비즈니스 로직·프레젠테이션 로직·데이터로 분리하는 디자인 패턴입니다. 요청 처리·응답 처리·로직 처리를 모듈화합니다.

구성역할
Controller서블릿이 담당. 요청 분석 → 필요한 모델 호출 → 결과를 보여줄 JSP 선택
ModelDB 연동 등 비즈니스 로직. DTO(VO)·DAO 클래스로 구성
ViewJSP가 화면 담당. 모델이 처리한 결과를 화면에 표시
🧪 실습 ① 컨트롤러(서블릿) — ModelServlet.java

모델 데이터를 만들어 request에 담고 뷰(mvc01.jsp)로 forward합니다.

⚠️ 주의
반드시 서블릿에서 서버를 먼저 실행해야 뷰(view)에 데이터가 전달됩니다. (JSP를 직접 실행하면 컨트롤러를 거치지 않아 ${...}가 비어 있음)
package com.space.mvc.model;

@WebServlet("/model") //http://localhost:8080/web02/model
public class ModelServlet extends HttpServlet {
    private static final long serialVersionUID = 1L;

    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        // 변수
        String season = "가을";
        
        // 배열
        String[] seasons = {"봄", "여름", "가을", "겨울"};
        
        // "season"을 모델로 뷰(mvc01)에 전달
        request.setAttribute("season", season);
        request.setAttribute("seasons", seasons);
        
        // "fruits"을 모델로 뷰(mvc01)에 전달
        List<String> fruits = Arrays.asList("사과", "바나나", "딸기");
        request.setAttribute("fruits", fruits);
        
        // "cars"을 모델로 뷰(mvc01)에 전달
        Map<String, Object> cars = new HashMap<>();
        cars.put("brand", "EV6");
        cars.put("year", 2025);
        request.setAttribute("cars", cars);
        
        // 포워딩: model -> view로 전달
        /*RequestDispatcher rd = 
                request.getRequestDispatcher("/mvc/mvc01.jsp");
        rd.forward(request, response);*/
        
        request.getRequestDispatcher("/mvc/mvc01.jsp").forward(request, response);
    }
}
🧪 실습 ② 뷰 — mvc01.jsp (EL + JSTL)
<h3>변수, 배열</h3>

🛒 MVC 실습 — 장바구니 프로그램 (Model 2)

기존 Model 1 방식의 장바구니(스크립틀릿으로 세션 리스트를 직접 다루던 addProduct.jsp 등)를 Model 2(MVC)로 변환한 예제입니다. 하나의 컨트롤러(CartServlet)에서 command 파라미터로 로그인·담기·목록을 분기합니다.

파일 이름계층역할
Cart.javaModel선택한 상품 목록을 담는 객체(세션에 저장)
CartServlet.javaController/cart — command로 로그인/담기/목록 분기 후 뷰로 forward
loginForm.jspView로그인 폼
selProduct.jspView상품 선택 + 추가 결과 메시지
cart.jspView담긴 상품 목록 출력
🔄 command 분기 흐름
/cart?command=login → 이름 세션 저장 → selProduct.jsp
/cart?command=add → 세션의 Cart에 상품 추가(+메시지) → selProduct.jsp
/cart?command=list → cart.jsp에서 ${cart.productList} 출력
🧪 ① Model — Cart.java
package com.space.mvc.model;

// 선택한 상품 목록을 보관 (세션에 저장되어 사용자별 장바구니 유지)
public class Cart {
    private List<String> productList = new ArrayList<>();

    // 상품 추가
    public void addProduct(String product) {
        productList.add(product);
    }
    // 목록 반환 (View에서 ${cart.productList}로 접근)
    public List<String> getProductList() {
        return productList;
    }
}
🧪 ② Controller — CartServlet.java
package com.space.mvc.controller;

import java.io.IOException;

import com.space.mvc.model.Cart;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import jakarta.servlet.http.HttpSession;

/**
 * 장바구니 컨트롤러(Controller)
 * - 하나의 서블릿에서 command 파라미터로 요청을 분기하는 MVC(Model 2) 방식.
 * - 요청 처리 후 결과 데이터를 Model에 담아 View(JSP)로 forward 한다.
 *
 * 요청 URL 예시)
 *   /cart?command=login  : 로그인 처리
 *   /cart?command=add    : 상품 담기
 *   /cart?command=list   : 장바구니 목록 보기
 */
@WebServlet("/cart") // http://localhost:8080/web02/cart
public class CartServlet extends HttpServlet {
    private static final long serialVersionUID = 1L;

    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        process(request, response);
    }

    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        process(request, response);
    }

    // 공통 처리 메서드
    private void process(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {

        // 한글 파라미터 처리
        //request.setCharacterEncoding("UTF-8");

        //hidden 타입으로 전달된 명령어
        String command = request.getParameter("command");
        HttpSession session = request.getSession();  //세션 객체 생성
        String view;

        if ("login".equals(command)) {
            // 로그인: 사용자 이름을 세션에 저장
            String username = request.getParameter("username");
            session.setAttribute("sessionName", username);
            view = "/products/selProduct.jsp";

        } else if ("add".equals(command)) {
            // 상품 담기: 세션의 Cart 모델에 상품 추가
            Cart cart = (Cart) session.getAttribute("cart");
            if (cart == null) {
                cart = new Cart();
                session.setAttribute("cart", cart); //세션 발급
            }
            String product = request.getParameter("product");
            cart.addProduct(product);

            // 추가 결과 메시지를 Model에 담아 View로 전달
            request.setAttribute("message", product + "가(이) 추가되었습니다.");
            view = "/products/selProduct.jsp";

        } else if ("list".equals(command)) {
            // 장바구니 목록 보기 (Cart 모델은 이미 세션에 있으므로 View로만 이동)
            view = "/products/cart.jsp";

        } else {
            // 기본: 로그인 폼
            view = "/products/loginForm.jsp";
        }

        // View로 포워딩
        request.getRequestDispatcher(view).forward(request, response);
    }
}

① 비즈니스 로직(상품 담기·세션 처리)을 JSP → CartServlet(Controller)로 이동, ② 데이터를 List 직접 저장 → Cart 모델 객체로 캡슐화, ③ 뷰의 스크립틀릿(<% %>)을 전부 제거하고 EL + JSTL로 출력, ④ 폼 action을 컨트롤러(/cart)로 향하게 변경.

🔗 ${pageContext.request.contextPath} 란?

JSP에서 현재 웹 애플리케이션의 컨텍스트 경로(루트 경로)를 출력하는 EL 표현식입니다. 자바 코드 <%= request.getContextPath() %>를 EL로 깔끔하게 쓴 것입니다.

구성의미
pageContextJSP 기본 내장 객체 (각종 정보 접근 관문)
.request요청 정보 객체(HttpServletRequest)
.contextPath요청의 컨텍스트 경로 = request.getContextPath()

컨텍스트 경로는 톰캣에 배포된 웹 앱을 구분하는 주소의 맨 앞부분입니다. 프로젝트가 web02로 배포되면:

http://localhost:8080/web02/cart
                      └──┬──┘
          contextPath = "/web02"

📌 왜 쓰는가 — 링크·form action 경로를 배포 환경과 무관하게 안전하게 만들기 위해서입니다.

작성 방법결과문제
action="cart" (상대경로)현재 URL 기준 이동현재 위치에 따라 엉뚱한 곳으로
action="/cart" (절대경로)localhost:8080/cart컨텍스트(/web02) 누락 → 404
action="${pageContext.request.contextPath}/cart"localhost:8080/web02/cart✅ 항상 정확
💡 정리
"지금 이 웹 앱의 시작 주소를 자동으로 넣어줘"라는 뜻입니다. 하드코딩된 /web02 대신 이 표현식을 쓰면 컨텍스트 이름이 바뀌어도(예: web02 → myapp) 코드를 고칠 필요가 없어 링크가 깨지지 않습니다.
