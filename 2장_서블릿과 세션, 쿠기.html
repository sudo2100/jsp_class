1 서블릿(Servlet)이란? & HttpServlet과 동작 흐름

🎯 학습목표
  • 서블릿의 개념과 서버 사이드 프로그램으로서의 역할을 설명할 수 있다.
  • 서블릿의 장점과 한계를 이해하고, JSP·Spring으로 발전한 배경을 안다.
  • Java EE(Jakarta EE) API 안에서 서블릿의 위치를 파악한다.

📖 서블릿의 개념

서블릿(Servlet)은 자바(Java) 기반의 웹 프로그래밍 기술로, 웹 서버에서 실행됩니다. 클라이언트(보통 웹 브라우저)의 요청(Request)을 처리하고 응답(Response)을 만들어 반환하는 서버 사이드 프로그램입니다.

💡 이름의 유래
Servlet = Server + Applet
웹 서버에서 실행되는 자바 클래스로, 클라이언트의 요청을 받아 동적 웹 페이지(DB 조회, 계산, 사용자 입력 처리 등)를 생성합니다. 일반적으로 HTTP 프로토콜 기반으로 동작하며, 가장 대표적인 구현체는 HttpServlet입니다.

✅ 서블릿의 장점

  • 자바 언어 기반 → 객체지향적이고 안정적
  • 플랫폼 독립적 → JVM만 있으면 어디서든 실행 가능
  • 강력한 라이브러리 & API 지원 (DB, 네트워크 등)
  • JSP, Spring Framework 같은 웹 기술의 기반

⚠️ 서블릿의 한계

  • 순수 서블릿으로 HTML을 출력하려면 out.println("<h1>...</h1>") 같은 코드가 복잡해짐
  • 뷰(View) 처리에 불편 → JSP와 함께 사용하면서 MVC 패턴이 도입됨
  • 이후 Spring, Spring Boot 같은 프레임워크가 발전하며 더 효율적인 개발 방식이 확산됨

🗺️ Java EE API 속의 서블릿

서블릿은 Java EE(현재의 Jakarta EE) 스펙에 정의된 웹 표준 API의 하나입니다. 서블릿 컨테이너(Tomcat 등)가 이 API를 구현하여 서블릿을 실행합니다.

🔄 HttpServlet과 동작 흐름

🎯 학습목표
  • HttpServlet이 무엇이며 왜 상속받아 사용하는지 설명할 수 있다.
  • doGet()과 doPost()의 차이를 구분한다.
  • 요청부터 응답까지 서블릿 실행 흐름을 순서대로 설명할 수 있다.

📖 HttpServlet이란?

  • HttpServlet은 Servlet의 대표적인 구현 클래스이다.
  • 클라이언트와 서버 간에 HTTP 프로토콜 기반의 요청과 응답을 처리하는 데 최적화된 서블릿이다.
  • 패키지 : javax.servlet.http.HttpServlet (Servlet 3.x까지) 또는 jakarta.servlet.http.HttpServlet (Servlet 4.x 이상, Jakarta EE)
  • 보통 Servlet 인터페이스를 직접 구현하지 않고, HttpServlet을 상속받아 필요한 메서드만 오버라이딩해서 사용한다.

🔧 HttpServlet의 주요 메서드

protected void doGet(HttpServletRequest req, HttpServletResponse resp)
        throws ServletException, IOException;

protected void doPost(HttpServletRequest req, HttpServletResponse resp)
        throws ServletException, IOException;
메서드처리 요청대표 예시
doGet()GET 요청 처리브라우저 주소창 요청, 링크 클릭 등
doPost()POST 요청 처리폼(form) 제출, JSON 데이터 전송 등

🔄 Servlet의 실행 흐름

클라이언트 요청이 들어오면 서블릿 컨테이너(Tomcat)가 아래 순서로 처리합니다.

[클라이언트(브라우저)]
          │  HTTP 요청
          ▼
   [웹 서버 + 서블릿 컨테이너(Tomcat 등)]
          │
          ├─> 요청 분석
          │
          ├─> 해당 서블릿 로딩 (없으면 메모리에 로드 & init() 실행)
          │
          ├─> service() 실행
          │        ├─ GET  → doGet()
          │        └─ POST → doPost()
          │
          └─> 결과 HTML/JSON 등 생성 → HTTP 응답
          ▼
[클라이언트(브라우저)]
💡 생명주기(Life Cycle) 메서드
init() : 서블릿이 처음 메모리에 로드될 때 한 번 실행(초기화) · service() : 요청마다 실행되어 doGet()/doPost()로 분기 · destroy() : 서블릿이 메모리에서 제거될 때 한 번 실행(정리)

📤 서블릿의 응답 처리 & HttpServletRequest · 회원가입 실습

🎯 학습목표
  • MIME-TYPE의 의미와 setContentType()의 역할을 설명할 수 있다.
  • PrintWriter로 HTML 응답을 생성하는 과정을 이해한다.
  • HelloServlet 실습으로 응답 처리 전체 흐름을 구현한다.

📖 응답 처리 4단계

  1. setContentType()으로 MIME-TYPE 지정
  2. 데이터를 출력할 PrintWriter 객체 생성
  3. 출력 데이터를 HTML 형식으로 만들기
  4. print() / println()으로 데이터 출력
💡 MIME-TYPE 이란?
톰캣 컨테이너에 미리 설정해 놓은 데이터 종류입니다. 서버에서 웹 브라우저로 데이터를 전송할 때 데이터 종류를 지정해서 전송합니다. 예) text/html, application/json, image/png

🧪 예제 : HelloServlet — 현재 시간 출력
@WebServlet("/hello") // URL 패턴 매핑
public class HelloServlet extends HttpServlet {
    private static final long serialVersionUID = 1L;

    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        // 응답 컨텐츠 타입 설정(type, 한글 인코딩)
        response.setContentType("text/html; charset=UTF-8");

        // 출력 스트림
        PrintWriter out = response.getWriter();

        // HTTP 응답
        out.println("<!DOCTYPE html><html>");
        out.println("<head><title>Hello Servlet</title></head>");
        out.println("<body><h2>Hello Servlet!</h2><hr>");
        out.println("현재 날짜와 시간은 " + LocalDateTime.now());
        out.println("</body></html>");
    }
}

📖 HttpServletRequest 란?

  • 클라이언트의 요청을 받아 서버가 처리할 수 있도록 HTTP 요청 메시지를 파싱하여 필요한 데이터를 제공한다.
  • 클라이언트의 요청 메시지, 요청 헤더, 요청 파라미터 등을 조회하는 데 사용된다.

🧪 예제 ② 처리 서블릿 — RegisterServlet

폼의 method가 post이므로 doPost()를 사용합니다.

@WebServlet("/register") // http://localhost:8080/register
public class RegisterServlet extends HttpServlet {
    private static final long serialVersionUID = 1L;

    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        // request.setCharacterEncoding("utf-8"); // 한글 깨짐(인코딩 설정)

        // 요청 입력값 받기
        String name  = request.getParameter("uname");
        String email = request.getParameter("email");

        // 응답 설정
        response.setContentType("text/html; charset=utf-8");
        PrintWriter out = response.getWriter();

        out.println("<!DOCTYPE html><html>");
        out.println("<head><title>회원 가입</title></head>");
        out.println("<body><h2>회원 등록 결과</h2><hr>");
        out.println("<p>이름: " + name + "</p>");
        out.println("<p>이메일: " + email + "</p>");
        out.println("<a href='/servlet/register.jsp'>다시 입력</a>");
        out.println("</body></html>");
    }
}

실습 2-1. 로그인 기능 구현

아래 조건대로 로그인 기능이 동작하도록 구현하세요.

  • 로그인 폼 : loginForm.jsp (아이디 · 비밀번호 입력)
  • 처리 서블릿 : LoginServlet.java
  • 서블릿 매핑 : /login
정답 예시 보기

① 로그인 폼 — loginForm.jsp

<h2>로그인</h2>
<form action="/login" method="post">
    <p>아이디 : <input type="text" name="userid"></p>
    <p>비밀번호 : <input type="password" name="pwd"></p>
    <input type="submit" value="로그인">
</form>

② 처리 서블릿 — LoginServlet.java

@WebServlet("/login")
public class LoginServlet extends HttpServlet {
    private static final long serialVersionUID = 1L;

    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        String id  = request.getParameter("userid");
        String pwd = request.getParameter("pwd");

        response.setContentType("text/html; charset=utf-8");
        PrintWriter out = response.getWriter();

        if ("admin".equals(id) && "1234".equals(pwd)) {
            out.println("<h2>" + id + "님 환영합니다!</h2>");
        } else {
            out.println("<h2>로그인 실패</h2>");
            out.println("<a href='/servlet/loginForm.jsp'>다시 로그인</a>");
        }
    }
}

폼의 method="post"이므로 서블릿에서는 doPost()로 받아 getParameter()로 아이디·비밀번호를 읽어 검증합니다.

3 세션·쿠키가 필요한 이유 & 세션 동작 원리와 JSESSIONID

🎯 학습목표
  • HTTP의 무상태(Stateless) 특성이 무엇인지 설명할 수 있다.
  • 상태 유지를 위해 세션과 쿠키가 등장한 배경을 이해한다.
  • 세션과 쿠키의 저장 위치 차이(서버 vs 클라이언트)를 구분한다.

📖 HTTP는 무상태(Stateless)다

HTTP는 요청(Request)과 응답(Response)으로 이루어지며, 특정 URL을 요청할 때마다 새로운 HTTP 요청이 생성됩니다. 그래서 요청들 사이에 상태를 유지할 방법이 없습니다.

💡 예시
/login.jsp에서 로그인을 했더라도 /boards 페이지로 이동하면 새로운 HTTP 요청이므로, 로그인했다는 정보를 확인할 수 없습니다.

이러한 HTTP의 무상태 특성을 극복하고자 나온 기술이 쿠키(cookie)와 세션(session)입니다. 이 둘은 특정 데이터를 저장해두고, 페이지를 이동하거나 새로고침하는 등 HTTP 요청이 매번 발생해도 특정 상태(데이터)를 유지할 수 있게 해줍니다.

🔑 세션(session)이란?

  • 클라이언트와 웹 서버 간의 상태를 지속적으로 유지하는 방법이다.
  • 사용자 인증을 통해 특정 페이지를 사용할 수 있도록 권한 상태를 유지한다.
  • 세션은 오직 웹 서버에 존재하는 객체로, 웹 브라우저마다 하나씩 존재한다. 따라서 브라우저를 닫기 전까지 웹 페이지를 이동하더라도 사용자 정보가 유지된다.
🛒 예시
웹 쇼핑몰에서 로그인 후 장바구니·주문 처리 같은 회원 전용 페이지를 이용하다가 다른 페이지에 갔다 돌아와도 로그인 상태가 유지됩니다.

⚖️ 세션 vs 쿠키 — 저장 위치가 다르다

구분세션(session)쿠키(cookie)
저장 위치웹 서버클라이언트(브라우저)
보안상대적으로 안전정보가 클라이언트에 남아 보안 취약
서버 부하서버에 저장 → 부하 발생클라이언트에 저장 → 서버 부하 감소
유지 기간브라우저를 닫으면 소멸(기본)설정한 유효기간까지 유지 가능

🔑 세션 동작 원리와 JSESSIONID

🎯 학습목표
  • 세션이 요청 → 발급 → 재요청으로 유지되는 프로세스를 설명할 수 있다.
  • JSESSIONID가 무엇이고 어떤 역할을 하는지 이해한다.

🔄 세션의 프로세스(Process)

확인 방법 : 브라우저 > 개발자도구(F12) > Network 탭

  1. 브라우저가 서버에 특정 페이지를 요청한다. 예) /createSession.jsp 요청
  2. 서버는 세션을 만들고 JSESSIONID 쿠키를 클라이언트에 발급한다. 이후 요청마다 브라우저는 이 세션 ID를 HTTP 요청 헤더에 포함해 보낸다.
  3. 서버는 요청 헤더의 JSESSIONID를 참조해 자신이 가진 세션 객체를 구분한다. 해당 세션에 로그인 정보가 담겨 있으면 로그인된 것으로 판단한다.

🆔 JSESSIONID란?

  • 톰캣 컨테이너에서 세션을 유지하기 위해 발급하는 키이다.
  • HTTP 프로토콜은 stateless하여 요청마다 새 연결이 생성되고 응답 후 끊기므로 상태를 유지할 수 없다.
  • 이를 위해 톰캣은 JSESSIONID 쿠키를 클라이언트에게 발급하고, 이 값을 통해 세션을 유지한다.

4 세션 생성·조회·삭제 & 유효시간 설정 & 장바구니 실습

🎯 학습목표
  • 세션 내장 객체의 주요 메서드를 알고 용도를 설명할 수 있다.
  • setAttribute()로 세션을 생성하고 getAttribute()로 조회한다.
  • invalidate()로 세션을 삭제(로그아웃)할 수 있다.

🔧 세션(session) 내장 객체 메서드

메서드설명
setAttribute(String name, Object value)세션 속성 이름 name에 value를 할당
getAttribute(String name)속성 이름이 name인 값을 Object형으로 반환 (형 변환 필요 : Object→String)

🧪 예제 ③ 로그인 처리·세션 발급 — session01Process.jsp

세션이 생성(부여)되는 시기는 로그인에 성공한 때입니다. session.setAttribute()로 세션 속성을 만듭니다. (속성 이름 userID, 값은 입력한 아이디(예: space/12345))

<%
    // 폼에 입력된 데이터 가져옴
    String userId = request.getParameter("uid");
    String userPw = request.getParameter("passwd");

    out.println("아이디: " + userId + ", 비빌번호: " + userPw);
    out.println("<br>");

    // 로그인 성공 여부
    if(userId.equals("space") && userPw.equals("12345")){
        session.setAttribute("userID", userId); //세션 발급
        out.println("세션이 발급되었습니다.");
    }else{
        out.println("<script>");
        out.println("alert('아이디나 비밀번호가 일치하지 않습니다.')");
        out.println("history.back()");
        out.println("</script>");
    }
%>

<p><%= session.getAttribute("userID") %>님 환영합니다!</p>
🧪 예제 ④ 모든 세션 삭제(로그아웃) — session03.jsp
<%
    String id = (String) session.getAttribute("userID");

    // 모든 세션 삭제
    session.invalidate();
%>
<p>세션을 삭제했습니다.</p>
💡 핵심
invalidate()는 현재 세션의 모든 속성을 한 번에 제거합니다. 로그아웃 기능에 사용합니다.

⏱️ 세션 유효시간 설정

🎯 학습목표
  • 세션 유효시간의 개념과 기본값(30분)을 안다.
  • setMaxInactiveInterval()로 유효시간을 변경할 수 있다.
  • web.xml의 session-config로 전역 설정하는 방법을 이해한다.

📖 세션 유효시간이란?

세션을 유지하기 위한 일정 시간으로, 기본값은 30분(1800초)입니다. 유효시간을 설정할 때는 session.setMaxInactiveInterval()을 초 단위로 사용합니다.

// 세션 유효시간 10분(600초) 설정
session.setMaxInactiveInterval(10 * 60);
🧪 예제 ① 유효시간 조회·변경 — timeout.jsp
<h3>세션 유효시간 변경 전</h3>
<%
    // 30*60 = 1800초
    int time = session.getMaxInactiveInterval();
    out.println(time + "초<br>");

    time = time / 60;
    out.println(time + "분<br>");
%>

<h3>세션 유효시간 변경 후</h3>
<%
    // 세션 유효 시간을 5분으로 설정
    session.setMaxInactiveInterval(5 * 60);

    // 5*60 = 300초
    time = session.getMaxInactiveInterval();
    out.println(time + "초<br>");

    time = time / 60;
    out.println(time + "분<br>");
%>

🧪 예제 ② 전역 설정 — web.xml (servers > web.xml)

특정 페이지가 아니라 애플리케이션 전체의 기본 세션 시간을 바꾸려면 web.xml에서 <session-timeout>(단위: 분)을 수정합니다.

<session-config>
    <session-timeout>30</session-timeout>  <!-- 기본 30분 -->
</session-config>

5 쿠키(cookie)의 개념과 동작 원리

🎯 학습목표
  • 쿠키의 개념과 클라이언트 저장 방식을 설명할 수 있다.
  • 쿠키의 작동 원리(생성 → 저장 → 전송)를 이해한다.
  • 쿠키의 장점과 보안 단점을 구분한다.

📖 쿠키(cookie)란?

  • 클라이언트와 웹 서버 간의 상태를 유지하는 방법으로, 서버가 클라이언트에 저장하는 정보이다.
  • 세션과 달리 상태 정보를 웹 서버가 아닌 클라이언트에 저장한다.
  • 클라이언트의 일정 폴더에 정보를 저장하므로 웹 서버의 부하를 줄일 수 있으나, 개인 정보 기록이 남아 보안에 문제가 있다.
💡 예시
웹 사이트를 처음 방문해 로그인 인증을 하면 아이디·비밀번호를 기록한 쿠키가 만들어지고, 다음부터는 별도 절차 없이 쉽게 접속할 수 있습니다.

🔄 쿠키(cookie)의 작동 원리

  1. 쿠키 생성 — 웹 서버가 응답하며 쿠키를 만든다. response.addCookie()
  2. 쿠키 저장 — 브라우저(클라이언트)의 쿠키 저장소에 저장된다.
  3. 쿠키 전송 — 이후 요청 시 브라우저가 쿠키를 서버로 보낸다. request.getCookies()
🗂️ 저장 위치
쿠키는 브라우저별 폴더에 파일로 저장됩니다. (예: Chrome 프로필 폴더 안의 쿠키 파일)

6 쿠키 생성·조회·삭제

🎯 학습목표

  • Cookie 객체 생성 → addCookie()로 클라이언트에 전송한다.
  • getCookies()로 조회하고 setMaxAge(0)로 삭제한다.

🧪 예제 ② 쿠키 생성 — cookie01_process.jsp

Cookie 클래스로 쿠키를 생성한 후 response.addCookie()로 로컬 컴퓨터(브라우저)에 전송합니다. (쿠키 이름 userId, 값 id)

<%
    String id  = request.getParameter("id");
    String pwd = request.getParameter("pwd");

    if (id.equals("today") && pwd.equals("1234")) {
        // Cookie(쿠키이름, 쿠키값)
        Cookie cookieId = new Cookie("userId", id);
        Cookie cookiePw = new Cookie("userPw", pwd);

        // 브라우저(로컬컴퓨터)로 보내줌
        response.addCookie(cookieId);
        response.addCookie(cookiePw);

        out.println("쿠키 생성이 성공했습니다.");
    } else {
        out.println("쿠키 생성이 실패했습니다.");
    }
%>
🧪 예제 ③ 쿠키 정보 조회 — cookie02.jsp

클라이언트에 저장된 모든 쿠키를 가져오려면 request.getCookies()를 사용합니다. (Cookie[] 배열 반환)

<%
    Cookie[] cookies = request.getCookies();
    out.println("현재 설정된 쿠키의 개수 => " + cookies.length + "<br>");
    out.println("===================================<br>");
    for (int i = 0; i < cookies.length; i++) {
        out.println("설정된 쿠키의 속성 이름 [" + i + "] : " + cookies[i].getName() + "<br>");
        out.println("설정된 쿠키의 속성 값 [" + i + "] : " + cookies[i].getValue() + "<br>");
        out.println("===================================<br>");
    }
%>

🧪 예제 ④ 쿠키 유효시간 설정 · 삭제 — expiry.jsp

쿠키는 기본적으로 브라우저를 닫으면 종료됩니다. setMaxAge(초)로 유효기간을 정하고, setMaxAge(0)이면 삭제됩니다.

<%
    Cookie[] cookies = request.getCookies();

    for (int i = 0; i < cookies.length; i++) {
        // 쿠키 유효 시간 설정(2분)
        cookies[i].setMaxAge(2 * 60);

        // 쿠키 삭제
        // cookies[i].setMaxAge(0);
        response.addCookie(cookies[i]);
    }

    response.sendRedirect("cookie02.jsp");
%>
⚠️ 주의
setMaxAge()로 값을 바꾼 뒤에는 반드시 response.addCookie()로 다시 전송해야 브라우저에 반영됩니다.
